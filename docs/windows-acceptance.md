# Windows 11 实机验收

本文件是可执行验收步骤，不代表已经执行。当前状态 **NOT_VERIFIED**。

## 最短启动

便携包解压后：

```powershell
.\SiLing-Voice.exe models download
.\SiLing-Voice.exe doctor
.\SiLing.exe
```

点击「开始监听」，等待状态为「等待唤醒」，说「你好司聆」，短提示音后说「打开记事本」。
R1 预期仅显示“打开记事本”文本并回到待机，**不会启动记事本**。
源代码用户也可以运行 `scripts/validate-windows.ps1`。

## 执行记录

记录 Windows 版本、CPU、内存、麦克风型号、采样率和构建 commit，逐项填写真实结果。
不要为通过验收而上传私人录音；录音样本由使用者保留在本机即可。

| 项目 | 步骤 | 要记录的证据 |
|---|---|---|
| 默认唤醒 | 安静环境重复 20 次，正常说「你好司聆」 | 实际触发数/20；失败时的距离和音量 |
| 中文转写 | 每次唤醒后分别说短句、数字、中英混合程序名 | 原句与识别结果，记录错字，不人工改成“准确” |
| 音量 | 说话并观察输入音量条 | 有动态响应，无输入时接近零 |
| 自定义词 | 修改为「小爱同学」，重新开始 | 新词触发、旧词不触发；恢复默认 |
| 无指令 | 说唤醒词后不说话 | 约 6 秒超时，无幻觉文字，回到待机 |
| 最长录音 | 连续说超过 15 秒 | 有界结束、一次转写、可再次唤醒 |
| 取消/静音 | 录音和识别阶段分别点击取消、静音 | 无晚到正文；设备占用释放；能恢复 |
| 麦克风权限 | 系统拒绝桌面麦克风访问后启动 | 明确报错，不死循环；恢复权限后可重试 |
| 独占设备 | 在音频控制面板用其他应用独占麦克风 | 设备打开失败提示及恢复行为 |
| 拔插 | 录音中拔出 USB 麦克风，再重连 | 有限次数恢复；重新选择设备后可监听 |
| 蓝牙 | 默认麦克风与蓝牙耳机切换 | 设备列表、采样率、识别结果 |
| 睡眠恢复 | 监听时睡眠，唤醒后测试 | 设备恢复；没有恢复时可手动重启监听 |
| 托盘 | 监听时关闭窗口，再从托盘打开 | 仍在监听，状态可见；托盘退出后进程消失 |
| 第二实例 | 已运行时再次启动 | 明确拒绝第二语音服务，不多开麦克风 |
| 误唤醒 | 电视/音乐/聊天背景连续 30 分钟 | 实际误触次数和环境；不是固定样本上的负例数 |
| 提示音回声 | 扬声器播放提示音，反复唤醒 | 不产生第二轮误唤醒；必要时关闭提示音对照 |
| 离线 | 已安装模型后断网执行上述正常闭环 | 全部在本机运行，无 API Key |
| 资源占用 | 任务管理器观察待机 10 分钟和 20 次识别 | CPU/内存实际数值，标明测量方法 |
| 完全退出 | UI 或托盘退出 | SiLing 与 SiLing-Voice 进程退出，麦克风权限指示消失 |
| 卸载 | NSIS 卸载后检查进程和安装目录 | 程序卸载；用户模型/配置如需删除手动清理 |

仅在实际 Windows 11 硬件按用例执行并留存证据后，才能标记相应条目 PASS_ON_DEVICE。
CI 中 Windows Server 的假设备测试和合成 WAV 推理不改变此状态。
